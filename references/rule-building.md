# 规则建设者作业规范

> 角色定位：制度与标准输出。把监管要求翻译成**可执行的审查标准**，并持续维护。
> 一句话流程：接收任务 → 优先检索知识库取权威原文 → 分四分支处理 → **二次反向复核** → 输出全套交付物。

---

## 一、六条刚性要求（制度是否合格的判据）

1. **建立专门制度**：明确审查主体、审查范围、审查要点、审查流程等操作性内容，确保审查有据可依。只写原则不写操作步骤的制度，视为不合格。
2. **纳入风控体系**：将消保审查纳入机构风险管理或内部控制体系，风控关口前移，线上线下并重。
3. **全环节覆盖**：覆盖设计开发、定价管理、协议制定、营销宣传等环节；审查对象包括可能影响消费者的**政策、制度、业务规则、收费定价、协议条款、宣传文本、销售话术**。
4. **动态更新**：结合投诉、诉讼、舆情、满意度调查情况更新审查要点，确保要点动态适用。
5. **硬性嵌入**：将审查嵌入审批流程，确保覆盖当年**全部新增和发生实质性改变**的产品与服务，并跟踪统计意见采纳情况。
6. **年度审视**：每年至少一次全面审视修订，与最新监管要求保持同步（9号令、银保监发〔2019〕38号、金规〔2025〕20号 等）。

> 这六条本身就是"存量制度合规校验"的检查表——逐条比对，缺哪条就补哪条。

---

## 二、四分支作业方法

### 分支 A：全新编制（制度 / 管理办法 / 操作指引）

**步骤**
1. 检索知识库取三类素材：外部监管强制要求、内部标准模板、现有规则库。
2. 梳理**法定动作清单**：把监管条文拆成"机构必须做什么"，逐条落到章节。
3. 搭章节框架（见 §三），先骨架后血肉。
4. 填充业务场景内容：结合本机构产品线、系统现状、审批流程写具体，不抄模板空话。
5. 输出初稿 → 进入第四步二次复核。

**易失分点**
- 只抄监管条文，不写"谁在什么节点做什么、多久做完、不做怎么办"。
- 缺"未审不上线"这类**强制约束机制**，制度就只是倡议书。
- 缺争议升级路径，实务中一旦冲突就卡死。

### 分支 B：存量制度合规校验与修订

**步骤**
1. 取现行监管条文（知识库优先，必要时联网核验最新版本）。
2. 与待核查制度**逐条比对**，产出三类标记：
   - **缺项**：监管有要求、制度没写 → 补。
   - **冲突**：制度写法与监管要求不一致 → 改。
   - **过期**：依据已废止或机构名称/条款号已变 → 换。
3. 输出**问题清单 + 修改建议 + 修订文稿 + 变更说明**四件套。
4. 变更说明要写清"改了什么、为什么改、依据哪一条、影响哪些流程"。

**比对口径**：以"机构是否履行了该义务"为准，不以"文字是否相似"为准。制度用不同表述但实质履行了义务，判为合规。

### 分支 C：审查要点库建立、更新与清理

**要点库的标准结构**（每条要点六要素齐全）

| 字段 | 说明 | 示例 |
|------|------|------|
| 要点编号 | 便于引用与追踪 | CP-MKT-012 |
| 适用对象 | 产品类型 / 材料形式 / 环节 | 保险·健康险·线上宣传 |
| 涉及权益 | 八项权益之一或多选 | 知情权、公平交易权 |
| 审查问题 | 可直接照着问的句子 | 是否同时以同等显著方式展示年缴总保费？ |
| 判断标准 | 什么算合规、什么算不合规 | 年缴金额字号不得小于日均金额的 80% |
| 依据 | 法规名称 + 条款号 + 内部制度条款 | 销售办法第17条(3) |
| 风险等级 | 命中后默认等级 | 高 |
| 更新记录 | 日期 / 原因 / 来源 | 2026-08，投诉联动，3起相关投诉 |

**维护规则**
- 新增触发：新规出台、监管处罚案例、投诉高频点、舆情事件、审查中反复出现的争议。
- 清理触发：依据废止、要点被新要点覆盖、连续两年零命中且无风险指向。
- **监管更新响应**：新规出台后应在约定工作日内完成解读并更新要点库，同时在要点中标注生效日期，避免"新规已生效、要点还用旧标准"。

### 分支 D：全场景专业答疑

**步骤**
1. 拆解问题，识别真正的问点（问的是"能不能做"还是"怎么做才合规"）。
2. 检索对应监管原文 + 内部制度条款。
3. 给结论 + 依据 + 边界条件（什么情况下结论会变）。
4. 附法条原文片段，便于提问者自行核对与留档。

**要求**：每条结论标注法规文号、条款号、内部制度条款。没有依据的，明说"暂无明确依据，以下为基于监管目的的推断，建议进一步确认"，不要伪装成确定结论。

## 三、制度文件章节框架

标准骨架（按机构实际增删，但**不可缺 3、5、6、8、9**）：

```
第一章 总则
  1.1 目的与依据（列明 9号令第9条、银保监发〔2019〕38号 等）
  1.2 适用范围（机构范围、产品范围、环节范围）
  1.3 术语定义（消保审查、送审材料、实质性改变、审查意见）
  1.4 基本原则（独立性、前置性、全面性、可追溯）

第二章 组织与职责
  2.1 董事会/消保委员会职责
  2.2 消保部门（审查主体）职责与独立性保障
  2.3 业务部门（送审主体）职责
  2.4 法务、合规、风险等协同部门职责
  2.5 审查人员任职条件与回避

第三章 审查范围（应审事项清单）
  3.1 按环节：设计开发 / 定价管理 / 协议制定 / 营销宣传
  3.2 按对象：政策制度、业务规则、收费定价、协议条款、宣传文本、销售话术、合作机构准入
  3.3 触发条件：新产品新服务；现有产品条款重大变化
  3.4 免审与简化审查情形（明确边界，防止滥用）

第四章 审查内容与要点
  4.1 六维审查框架
  4.2 八项权益映射
  4.3 分产品线审查要点（引用《审查要点库》）
  4.4 要点库的维护责任与更新机制

第五章 审查流程与时限
  5.1 送审（材料清单、送审表、自评估）
  5.2 受理与分办（受理条件、补正要求）
  5.3 审查（深度分级 L1/L2/L3、审查方法）
  5.4 出具意见（意见类型、格式、签批）
  5.5 反馈与整改（整改任务单、复查）
  5.6 归档（归档要件、保存期限）
  5.7 各环节标准时限与超时处理

第六章 审查意见的类型与效力
  6.1 通过 / 有条件通过 / 不通过 的判定标准
  6.2 意见效力：不通过不得上线；有条件通过须整改后复查
  6.3 意见的变更与撤回

第七章 争议解决与升级
  7.1 沟通协商（时限、参与方）
  7.2 跨部门协调会
  7.3 消保委员会审议
  7.4 决策记录与责任认定（谁决策谁负责）
  7.5 例外审批通道（先上线后补审的条件与时限）

第八章 强制约束机制
  8.1 系统阻断：未审查/未归档不得上线
  8.2 绕过审查的告警与问责
  8.3 采纳情况跟踪与考核挂钩
  8.4 应审尽审专项排查（频次、方法、报告）

第九章 监督与问责
  9.1 内部审计（周期、覆盖范围）
  9.2 质量抽检与复盘
  9.3 违规情形与问责措施

第十章 记录、归档与保密
  10.1 归档要件与保存期限
  10.2 可追溯要求（意见、整改、决策全程留痕）
  10.3 保密义务

第十一章 附则
  11.1 与上位制度的关系
  11.2 解释权
  11.3 生效日期与过渡安排
  11.4 年度审视安排
```

配套附件：审查送审表、审查意见单、整改任务单、审查台账、应审事项清单、审查要点库、质量抽检表。

## 四、二次合规复核（不可跳过）

制度/要点/答复生成后，**必须**做一次反向复核——把成稿重新对照知识库与法规库走一遍：

1. **查漏**：监管强制要求是否逐条落地？有没有"应该写但没写"的。
2. **查冲突**：新写内容与机构现有其他制度是否矛盾（尤其是审批流程、问责条款）。
3. **查失效**：引用的依据是否已废止、机构名称是否已变更、条款号是否已调整。
4. **查可执行**：每个"应当"是否都有明确的责任主体和时限？没有的补上，否则落地时会互相推。

复核结果写进交付物的"合规复核说明"章节：已核对法规清单、核对结果、待确认项。**有未解决项就如实写，不要用"基本合规"糊过去。**

## 五、交付物与命名

| 任务类型 | 交付物 | 命名 |
|----------|--------|------|
| 制度编制/修订 | 完整制度文件 + 变更说明 + 合规复核说明 | `{制度名称}_v{版本号}.md` |
| 存量校验 | 问题清单 + 修订建议 + 修订稿 + 变更说明 | 同上，版本号递增 |
| 要点库维护 | 更新后的要点库 + 更新记录 | `审查要点库_v{版本}.md` |
| 专业答疑 | 答复正文 + 依据原文附件 | `答疑_{问题简述}_{日期}.md` |

交付物开头统一写"背景与依据"（任务类型、法规依据、参考模板），结尾统一写"合规复核说明"与"附件"。
