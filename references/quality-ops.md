# 质量管理者作业规范

> 角色定位：让审查体系本身变得更好。连接"规则建设"与"审查执行"的枢纽，驱动体系持续进化。
> 一句话：审查管理不是"做完就完"，而是通过流程闭环、质量管控、采纳追踪、规则迭代、知识沉淀，让体系自我进化。

---

## 一、流程标准化与闭环管控

### 五步闭环

```
送审 → 审查 → 反馈 → 争议 → 归档
```

每一步必须完成才能进入下一步，**不允许线下流转后补录**。

| 环节 | 必达要求 | 标准时限（建议口径） |
|------|----------|---------------------|
| 送审 | 送审表 + 材料齐套 + 业务自评估 | — |
| 受理 | 材料齐套性检查，不齐发补正通知 | 1 个工作日 |
| 审查 | 按 L1/L2/L3 深度出具意见 | L1：2 日；L2：3–5 日；L3：5–10 日 |
| 反馈 | 业务部门回复采纳情况（含不采纳书面理由） | 3 个工作日 |
| 争议 | 按升级路径处理并留书面记录 | 5 个工作日（每级） |
| 归档 | 意见、整改、决策全程留痕 | 整改完成后 5 个工作日 |

### 三项硬机制

1. **未归档不上线**：审查单必须完成归档才允许上线。绕过归档上线的，触发系统阻断或告警。
2. **退出复查**：结论为"有条件通过"的，整改完成后系统生成复查任务，审查人员确认整改质量后方可归档。
3. **争议升级留痕**：消保部门内部讨论 → 跨部门协调会 → 消保事务委员会审批；每个节点书面记录，作为"谁决策、谁负责"的依据。

### 状态看板

台账须实时呈现：待审、审查中、待反馈、争议中、待复查、待归档、已归档。管理人员可按部门、产品线、逾期状态筛选。

## 二、审查意见质量管控

### 质量抽检

- **频次**：每季度一次，从已归档审查单中随机抽取（建议不低于 10%，高风险产品线提高比例）。
- **方法**：对照《质量检查表》，用**最新**规则库复核，而不是用当时的口径。
- **两类重点问题**：
  - **漏判**：真风险没被发现（严重）。
  - **过度审查**：合规表述被拦下（同样要复盘，它损耗审查公信力）。
- **结果运用**：纳入审查人员绩效；优秀案例进案例库，漏判案例复盘上会。

### 质量检查表（评分维度）

| 维度 | 检查点 | 权重 |
|------|--------|------|
| 明确性 | 问题描述是否具体到句、位置；是否避免"存在合规风险"这类空话 | 25% |
| 依据准确性 | 条款号是否正确、是否现行有效、是否精确到条 | 30% |
| 建议可操作性 | 是否写清改哪句、改成什么；是否有替代方案 | 25% |
| 完整性 | 六维+三横切是否覆盖；高/中/低定级是否合理 | 15% |
| 留痕规范 | 原文引用是否可定位；结论是否唯一 | 5% |

评分 ≥85 优秀、70–84 合格、<70 需复盘重审。

### 优秀意见案例库

每季度评选"最具洞察力意见""最佳解决方案"，入《审查优秀案例库》作为培训素材。评选标准：提前预判了后来真实发生的投诉/处罚风险。

## 三、采纳追踪与闭环验证

### 采纳追踪

- 系统记录采纳状态：**采纳 / 部分采纳 / 不采纳**。
- "不采纳"强制填写书面理由（技术实现困难、与产品核心逻辑冲突、成本不可承受等），并进入后续确认流程。
- 按月/季度统计采纳率并公示，纳入部门消保考核。

### 整改追踪

- "有条件通过"自动生成整改任务单：责任人、事项、时限。
- 到期前提醒，完成后触发复查；复查通过才归档。
- 超期未完成自动升级告警至部门负责人、分管领导。

### 效果验证

- 时点：产品上线后 6 个月，或出现相关投诉时。
- 判断：
  - 意见被采纳且无投诉 → 有效拦截。
  - 意见被采纳但仍出现投诉 → 追问两件事：**变更方案是否打折扣执行？** 还是**审查本身漏判了其他风险**？
  - 意见未被采纳且出现投诉 → 进入复盘，评估当初不采纳决策的责任。

## 四、应审尽审管控

### 三件事

1. **应审事项清单**：列举所有需审查的事项类型（产品设计、定价调整、协议制定、营销宣传、合作机构准入、制度规则等）。每年更新一次，新业务形态及时纳入。
2. **系统阻断**：核心业务系统/上线流程嵌入审查强制节点；未审查或未归档自动阻断。设"例外审批"通道——确需先上线后补审的，须经消保委员会审批并设定补审时限。
3. **专项排查**：每半年一次，比对"已上线产品/服务清单"与"已审查清单"，识别未审直接上线的情况。发现漏审及时补审，已造成风险的启动问责。

### 排查方法（可执行）

```
① 取数：业务系统导出的上线清单（含上线日期、产品编码、渠道）
② 取数：审查台账（含审查完成日期、归档日期）
③ 左连接匹配：以上线日期为基准，检查上线前是否已有归档审查记录
④ 分类：已审 / 先上线后补审 / 从未审查 / 审查记录与产品不匹配
⑤ 输出：漏审清单 + 原因（流程缺失/系统未阻断/业务绕行/口径差异）+ 整改建议
```

**口径要点**：审查必须在**上线前**完成。上线后补审的，即使结论是"通过"，也属于流程违规，应单独统计。

## 五、动态优化与规则迭代

### 四类触发源

| 触发源 | 动作 | 时限建议 |
|--------|------|----------|
| **监管新规** | 解读 → 更新要点库 → 通知业务部门 | 新规发布后约定工作日内 |
| **同业处罚** | 反查"我们是否也有类似风险""规则是否覆盖该风险" | 案例公布后 2 周内 |
| **投诉联动** | 每月分析投诉数据，提炼高频问题；反查规则覆盖情况：未覆盖→新增；已覆盖但漏审→复盘 | 月度 |
| **舆情监测** | 涉及本机构或同业的消保舆情，分析是否暴露审查盲区 | 事件发生后即时 |

### 投诉反查的三个问题

1. 这个问题在我们的审查要点库里有没有？
2. 有的话，为什么这次没审出来？（要点表述太抽象 / 审查员未执行 / 材料未提供相关信息）
3. 没有的话，应该新增什么要点、适用什么产品范围、定什么风险等级？

### 正向反馈闭环

识别"因审查优化避免了重大投诉或监管处罚"的案例，入《审查价值案例库》，用于向上汇报与内部宣传。表彰提出前瞻性风险的审查人员。

**为什么重要**：审查岗的工作成果天然是"没发生的事"，不做价值显性化，资源与话语权会持续被压缩。

## 六、知识沉淀与案例管理

### 审查案例库

每个案例五段式：送审概要 → 核心风险点 → 审查意见 → 整改情况 → 上线后效果验证。

支持按业务条线、风险类型、涉及权益、产品类型打标签查询。

### 季度知识提炼

每季度评选一个"最佳案例"和一个"反思案例"，附专业解读与复盘，转化为培训素材。

### 外部知识吸收

持续收集监管通报、处罚决定、行业研讨、专业文章，纳入行业知识库。引用外部材料同样要核验来源，不把自媒体解读当监管口径。

## 七、统计口径（必须可复算）

| 指标 | 公式 | 说明 |
|------|------|------|
| **审查覆盖率** | 已审查数 ÷ 应审查数 | 分子分母同一时间窗、同一清单口径；先上线后补审不计入"已审查" |
| **意见采纳率** | 采纳的实质性意见条数 ÷ 提出的实质性意见条数 | 只统计实质性意见；"建议优化表述"这类不计数；部分采纳按 0.5 计 |
| **整改完成率** | 按期完成整改项数 ÷ 应整改项数 | 超期完成不计入按期 |
| **平均审查时长** | Σ(意见出具日 − 受理日) ÷ 审查单数 | 剔除业务部门补正等待时间 |
| **漏判率** | 抽检发现漏判条数 ÷ 抽检意见总条数 | 按季度 |
| **过度审查率** | 抽检认定不成立条数 ÷ 抽检意见总条数 | 按季度，与漏判率并列呈现 |
| **投诉关联率** | 上线后6个月内产生相关投诉的产品数 ÷ 期间上线产品数 | 需定义"相关投诉"的匹配规则 |

**报表纪律**：任何指标都要能追溯到原始台账；同比环比要说明口径是否变化；发现指标异常先查口径，再下结论。

## 八、输出格式

```markdown
## [报告标题]

### 数据概览
| 指标 | 数值 | 环比 | 说明 |

### 详细分析
[按维度展开：数量与结构、问题分布、部门/产品线对比]

### 问题与建议
| 序号 | 问题描述 | 风险等级 | 改进建议 | 责任方 | 时限 |

### 趋势对比
[与上期对比，说明变化原因]

### 引用来源
[知识库文件名及数据来源]
```

命名：`季度审查分析报告_{YYYY}Q{N}.md`、`审查质量抽检报告_{YYYY}Q{N}.md`、`应审尽审排查报告_{YYYY}H{N}.md`

## 九、常见失效点

1. **只在纸上闭环**：制度写了"未归档不上线"，系统没阻断，等于没有。
2. **采纳率虚高**：靠"建议优化""建议关注"这类软意见刷采纳率，实质问题没推动。
3. **抽检只查漏判**：不查过度审查，团队会越来越保守，最后审查意见没人当回事。
4. **要点库只增不减**：几年后几千条要点，没人看得完，实际执行的是最熟的那十几条。
5. **效果验证缺失**：不回头看上线后结果，审查就永远学不到"哪些判断是对的"。
