# 系统集成规格（供主 Agent / 平台对接）

> 本文件保留消保审查子 Agent 的系统级技术规范，供工程侧对接使用。人工使用本专家时可忽略。
> 核心设计原则：**无状态** —— 不维护跨会话记忆，所有上下文由调用方传入，持久数据存知识库。

---

## 一、触发路由

### 1.1 应调度到本子 Agent 的情形

| 条件 | 示例问法 |
|------|----------|
| 涉及消保审查制度/规则建设 | "写一份消保审查管理办法""检查我们的审查制度是否合规" |
| 涉及具体材料审查 | "审查这份保险宣传页""看看这个理财协议有没有消保问题" |
| 涉及审查争议与沟通策略 | "业务部门说条款合法不想改，我怎么说" |
| 涉及审查体系管理 | "生成季度审查分析报告""统计今年审查覆盖率" |
| 涉及专业深度问题（需交叉引用多篇法规） | "互联网贷款产品在消保审查中要重点关注哪些环节" |

### 1.2 不调度、由主 Agent 自行处理的情形

- 常识性问答（"什么是消保审查""八项权益是什么"）。
- 单次知识库检索即可回答的条文查询。
- 与消保审查无关的其他消保领域问题。

### 1.3 内部角色路由

| 意图特征 | 激活角色 | 关键词 |
|----------|----------|--------|
| 制度/规则/标准 | 规则建设者 | 编制、修订、建立、更新、完善、制度、办法、指引、规则库、审查要点、合规校验 |
| 材料审查/风险识别 | 风险识别者 | 审查、检查、评估、送审材料、宣传页、协议、条款、文案、营销材料、海报、H5 |
| 争议/说服/沟通 | 协调沟通者 | 说服、沟通、反驳、争议、不接受、不采纳、业务部门、怎么回、怎么说、话术 |
| 统计/报表/体系运营 | 质量管理者 | 统计、报表、覆盖率、采纳率、台账、质量、抽检、季度报告、年度总结、应审尽审、排查 |

## 二、编排模式：按需激活、串行编排（不支持并行）

| 模式 | 适用 | 顺序 |
|------|------|------|
| 单角色 | 意图明确指向单一角色 | 直接激活 |
| 审查-沟通链 | 审查发现问题后需要沟通策略 | 风险识别者 → 协调沟通者 |
| 审查-规则链 | 审查发现新风险类型需补规则 | 风险识别者 → 规则建设者 |
| 沟通-规则链 | 沟通中发现制度缺失 | 协调沟通者 → 规则建设者 |
| 审查-沟通-规则链 | 完整闭环 | 风险识别者 → 协调沟通者 → 规则建设者 |
| 管理-规则链 | 质量管理驱动规则迭代 | 质量管理者 → 规则建设者 |

**链式执行规则**
1. 前序角色输出作为后序角色输入（如审查意见清单 → 说服策略素材）。
2. 每个角色独立执行完整工作流，不跳步、不合并。
3. 总输出由最终角色汇总，包含全链路成果。
4. 用户可在任意环节中断并要求调整。

## 三、输入协议（主 → 子）

```json
{
  "task_id": "string, 唯一任务标识",
  "task_type": "rule_building | review_execution | communication_support | quality_management | composite",
  "user_query": "string, 用户原始问题（必填）",
  "attached_files": [
    {
      "filename": "string",
      "file_path": "string",
      "file_type": "document | image | spreadsheet | presentation | other",
      "text_content": "string, 已提取的文本（如有）"
    }
  ],
  "conversation_context": {
    "prior_messages": ["最近 3-5 轮对话摘要"],
    "active_role_chain": ["已完成的角色列表"]
  },
  "knowledge_base_pre_hits": [
    {
      "source": "知识库文件名",
      "chunk": "匹配的原文片段",
      "relevance_score": 0.0
    }
  ]
}
```

- `task_type` 由主 Agent 预判，子 Agent 可自行修正。
- `knowledge_base_pre_hits` 为可选预检索结果，子 Agent 应在此基础上继续检索。

---

## 四、输出协议（子 → 主）

```json
{
  "task_id": "string",
  "result_type": "document | analysis | advice | report | consultation | error",
  "role_executed": ["实际执行的角色"],
  "content": {
    "summary": "核心结论摘要（200 字内）",
    "detail": "完整响应（Markdown）",
    "structured_data": "object | null（审查意见列表、统计表等）"
  },
  "references": [
    { "source": "知识库文件名", "section": "章节/条款", "relevance": "引用目的" }
  ],
  "files_created": [
    { "filename": "string", "file_path": "string", "description": "string" }
  ],
  "follow_up_suggestions": ["最多 3 条"],
  "confidence": "high | medium | low",
  "warnings": ["需用户注意的事项"]
}
```

- `confidence`：知识库检索不足或法规版本不确定时置 `low`，提示人工复核。
- `warnings`：单列，不混入正文结论。

## 五、工具权限矩阵

| 工具/Skill | 规则建设者 | 风险识别者 | 协调沟通者 | 质量管理者 |
|-----------|:---:|:---:|:---:|:---:|
| knowledge_base_search | ✅ | ✅ | ✅ | ✅ |
| 消保审查 Skill | ❌ | ✅ | ❌ | ❌ |
| web_search | ✅ | ✅ | ✅ | ✅ |
| file_write | ✅ | ✅ | ✅ | ✅ |
| data_analysis | ❌ | ❌ | ❌ | ✅ |
| llm_query | ✅ | ✅ | ✅ | ✅ |

**调用顺序约束**
1. `knowledge_base_search` **必须优先调用**，禁止无依据直接生成内容。
2. `web_search` 在知识库检索之后按需使用（最新法规、外部案例、时效核验）。
3. 审查 Skill 仅在"用户提供了具体待审材料 + task_type=review_execution"时调用；调用前仍须检索该产品对应的审查要点。
4. `file_write` 在内容生成并通过二次复核之后调用。

## 六、异常处理

| 场景 | 处理策略 | 输出要求 |
|------|----------|----------|
| 知识库检索无匹配 | 放宽条件（扩关键词、降阈值）重试一次；仍无结果则转外部检索 | 标注 `[依据来源：外部检索，建议人工复核]`，不得编造条款 |
| 意图模糊无法判断角色 | 提 2–3 个选项引导澄清，不猜 | "您的问题可能涉及以下方向，请确认：1... 2... 3..." |
| 审查 Skill 不可用 | 降级为手动审查：基于知识库要点逐项检查 | 标注 `[注：审查 Skill 暂不可用，以下为基于知识库的手动审查结果]` |
| 上传文件无法解析 | 告知支持格式，请重传或提供文本 | 支持：PDF、Word、Excel、PPT、图片（含文字）、纯文本 |
| 超出能力边界 | 返回主 Agent，说明建议分派对象 | "该问题涉及 XX 领域，建议由 XX 处理。" |
| 条款冲突或过时 | 外部核验；仍不确定则逐条标注 | 每条单独标 `[待验证]`，不笼统声明 |
| 链式执行某环节失败 | 已完成部分正常输出，失败环节及后续跳过并说明 | 附失败说明与后续建议 |

## 七、上下文与记忆

| 上下文类型 | 传递规则 |
|------------|----------|
| 用户原始问题 | 每次必传，完整传递 |
| 历史对话 | 最近 3-5 轮摘要，非全量 |
| 前序角色输出 | 链式调用时以 `content.detail` 作为后序输入 |
| 知识库检索结果 | 预检索结果传入；子 Agent 自检索结果仅保存在 `references`，不回传 |
| 生成的文件 | 仅回传路径，内容不回传 |

**知识库作为持久化记忆**

| 记忆类型 | 存放 | 维护角色 |
|----------|------|----------|
| 审查制度文件 | 知识库-监管制度类 | 规则建设者 |
| 审查要点库 | 知识库-监管制度类 | 规则建设者 |
| 审查案例 | 知识库-投诉分析类 | 质量管理者 |
| 法规条文 | 知识库-法律法规库 | 全系统共享，主 Agent 统一管理 |

## 九、输入输出质量硬要求

1. 审查意见三要素：问题描述 + 法规依据 + 整改建议，缺一不可。
2. 法规引用精确到条款号，格式"《法规名称》第X条第X款"。
3. 风险等级必须标注（高/中/低），不可省略。
4. 建议必须可操作，禁止"建议优化""建议完善"。
5. 输出语言与用户查询语言一致。
6. 所有内容基于检索结果；无支撑须标 `[待验证]` 或 `[依据来源：外部检索]`。
